# WordReplica Lekta Target-DOCX Local POC Design

**Date:** 2026-08-17
**Status:** Approved companion design
**Branch:** `automation-dev`

## Purpose

Add the smallest reusable execution boundary that lets WordReplica visibly reconstruct a corrected DOCX produced by Lekta while treating the user's original DOCX as immutable evidence.

The canonical cross-repository design is:

`Lekta/docs/superpowers/specs/2026-08-17-lekta-wordreplica-target-docx-poc-design.md`

This companion specifies only the WordReplica-side behavior needed for the first real-Word proof on:

`C:\Users\PC\Documents\Kalogjera - seminar Havel.docx`

## Inputs

The local POC receives explicit paths to:

- original DOCX;
- corrected target DOCX generated by Lekta;
- signed Repair Contract v1;
- development public-key configuration.

The runner never infers files from broad folders and never substitutes the newest file by timestamp.

Repair Contract v1 binds `sourceSha256`, `sourceSize`, `sourceFileName`, `targetSha256`, `targetSize`, `targetFileName`, the approved requests, policy, engine range, job identity and expiry.

## New application boundary

Introduce a local repair-package service above `RebuildService`; do not place Lekta-specific validation inside the renderer or Word controller.

Its responsibilities are:

1. load and strictly parse the package;
2. verify signature and trusted key identifier;
3. validate time and engine compatibility;
4. verify exact source and target identities;
5. create a run binding over contract digest, source hash and target hash;
6. choose a safe new output path;
7. invoke interactive reconstruction using the corrected target as the reconstruction source;
8. verify the produced output against the target;
9. recheck the original source hash;
10. emit a completion report.

The existing parser, blueprint compiler, fast table path, interactive controller, checkpoints and final QA remain the reconstruction implementation. Lekta repair semantics are not added to WordReplica.

## Run binding and resume

The interactive checkpoint is extended or wrapped with a POC binding containing:

- `job_id`;
- canonical contract SHA-256;
- original source SHA-256;
- corrected target SHA-256;
- output path;
- engine version.

Resume is rejected before Word opens if any bound value changes. The existing semantic event checkpoint remains authoritative for reconstruction position.

## Path safety

The original, target and output paths must resolve to three different files. Output naming starts from the signed suggested filename and resolves collisions by creating a new non-overwriting name.

The service must reject:

- source overwrite;
- target overwrite;
- output outside the explicitly selected destination directory;
- reserved Windows names;
- path aliasing through relative segments or case differences.

## Word ownership safety

All existing AGENTS.md process rules remain mandatory:

- one active owned automation run;
- never globally terminate `WINWORD.EXE`;
- never close unrelated documents;
- terminate only an exact owned PID when creation FILETIME evidence still matches;
- ownership uncertainty is a fail-safe stop, not permission to clean up broadly.

The POC must be tested with an unrelated Word document open.

## Verification and reporting

The corrected target is the fidelity reference. The original is checked only for identity preservation.

The completion report records:

- validation results for contract, signature, policy and all bound artifacts;
- source, target and output identities;
- original unchanged;
- output path;
- reconstruction project ID and blueprint fingerprint;
- timing by phase;
- Word ownership evidence;
- OpenAndRepair result;
- visible-text and Fields.Update equality;
- G0-G9 results;
- terminal status and reasons.

No FULL PASS is possible unless all required contract gates pass and the original remains byte-identical.

## Failure and fail-safe behavior

Invalid package data fails before any Word controller is constructed.

During reconstruction, existing safe pause and checkpoint behavior is retained. A package-level resume may continue only after package binding validation succeeds. Unexpected regression or insufficient ownership/diagnostic evidence invokes the AGENTS.md fail-safe and stops further autonomous mutation.

## TDD sequence

Implementation begins with tests for:

1. strict contract/package parsing;
2. signed target identity verification;
3. source/target/output path separation;
4. run binding persistence and resume rejection;
5. no Word startup on preflight failure;
6. delegation to interactive reconstruction with target as source;
7. original hash recheck and completion-report classification;
8. unrelated Word-instance preservation.

Each production fix follows the mandatory local loop: evidence, first root cause, RED regression test, smallest fix, GREEN, full suite, real Word run and G0-G9 comparison.

## Acceptance

The first POC checkpoint is reached only after the Kalogjera package completes two consecutive real-Word FULL PASS runs on the same `automation-dev` commit, including an open unrelated Word document and a separately verified interruption/resume scenario.

This checkpoint does not authorize promotion to `main`; the existing promotion gate remains authoritative.
